# リモート MCP の OAuth 対応

## 背景

リモート MCP（`/mcp`）は設定画面で発行する API トークンを `Authorization: Bearer` で受けるだけだった。
ChatGPT や claude.ai のコネクタはヘッダーを手で設定できず、MCP の認可仕様（OAuth 2.1）でしか
非公開のサーバーに接続しない。そのため、これらのクライアントからは使えなかった。

## 決定

edane 自身を OAuth 2.1 の認可サーバーにする。外部の認可サーバー（Auth0 など）は使わない。
ログインは既存の Google ログイン（セッション Cookie）をそのまま使い、同意画面だけを足す。

- **発見**: `/mcp` の 401 は `WWW-Authenticate` の `resource_metadata` で保護リソースのメタデータ（RFC 9728）を示す。
  そこから認可サーバーのメタデータ（RFC 8414、issuer = オリジン）へ辿らせる。
- **クライアント登録**: 動的クライアント登録（RFC 7591）だけ。誰でも登録できるが、アクセスを得るのは
  ユーザーが同意画面で許可したときだけ。Client ID Metadata Document（URL を client_id にする方式）は、
  サーバーから任意の URL を取りに行く必要がある（SSRF の面が増える）ので今回は入れない。
- **リダイレクト URI**: 登録時に https、ループバックの http、アプリ独自のスキーム（逆ドメイン形式か、既知の MCP クライアントのもの）に限る。認可要求では完全一致
  （ループバックだけはポートを問わない。RFC 8252）。一致しない・クライアントが無いときはリダイレクトせずエラー画面。
- **PKCE（S256）必須**。公開クライアントが基本で、`client_secret_post` / `client_secret_basic` での登録を
  求められればシークレットも発行する（クライアントによってはこちらで登録してくるため）。
- **スコープ**: `notes` の 1 つだけ。API トークンと同じく全ノートの読み書き。知らないスコープは無視する。
  `resource`（RFC 8707）は `/mcp` 以外なら断る。
- **トークン**: 不透明なランダム文字列で、DB にはハッシュだけを置く（API トークンと同じ）。JWT にしないのは、
  検証する側が `/mcp` だけで、毎回 D1 を 1 回引けば済み、解除が即時に効くから。
  アクセストークン 1 時間、リフレッシュトークン 90 日で、リフレッシュのたびに両方入れ替える。
  アクセストークンは接頭辞（`edane_oat_`）で API トークンと見分け、`/mcp` の検索を 1 回に保つ。
- **付与（grant）**: クライアント × ユーザーの 1 行が、その時点のアクセス／リフレッシュの組を持つ。
  設定画面の「接続中のアプリ」で行を消すと、そのクライアントは即座に使えなくなる。
- **同意画面**: Inertia のページ（`pages/OAuth/Authorize.tsx`）。素のフォーム POST で、サーバーは
  隠しフィールドを GET と同じ検証に通し直す。POST は Origin を確かめ（Cookie が SameSite=Lax なので
  他サイトからは元々ログイン状態で届かない）、ページは iframe への埋め込みを禁じる（クリックジャッキング対策）。
  クライアント名は自己申告なので、戻り先（リダイレクト URI のオリジン）も表示する。
- **未ログイン**: 同意画面の URL を短命の Cookie に覚えて Google ログインへ送り、callback がそこへ戻す。

## mount の順序

メタデータ・登録・トークンの各エンドポイントは Cookie を読まないので、`/mcp` と同じくセッション
ミドルウェアより前に置く（`oauthServerRoutes`）。同意画面と「接続中のアプリ」の API はログイン中の
ユーザーが要るので、セッション・Inertia ミドルウェアより後（`oauthSessionRoutes`）。

## 行の掃除と登録の制限

動的登録は認証なしなので、放っておくと使われない行が溜まる。

- **掃除**: クライアント登録（`OAuthStore.createClient`）が、登録と同じ 1 回の batch で
  期限切れの認可コード、リフレッシュトークンが切れた付与、誰にも許可されないまま 1 日経ったクライアントを消す。
  溜まる原因は誰でもできる登録なので、そこで片付ければ溜まらない。cron は使わない。
  どこより前を消すかはルートが決め、ストアは渡された時刻で消すだけ。
- **許可されたことのあるクライアントは消さない**（`oauth_clients.authorized_at`）。コネクタは登録した
  client_id を持ち続けるので、接続を解除したり付与が切れたりした後に同じコネクタで再接続できるようにする。
  行が増えるのは実際に許可したクライアントの分だけ。
- 「接続中のアプリ」はリフレッシュトークンが切れた付与を出さない（掃除を待たずに隠す）。
- **登録のレート制限**: `POST /oauth/register` は Workers の Rate Limiting（`OAUTH_REGISTER_LIMITER`、
  IP ごとに 1 分 10 件）を超えると 429。

## 既知の制限

- リフレッシュトークンの再利用検知（古いトークンが使われたら付与ごと無効にする）はしていない。

## 互換性と展開

D1 migration `0011_oauth.sql` と `0012_oauth_cleanup.sql` が必要（0012 は既存の付与を持つクライアントを
許可済みとして埋める）。`wrangler.jsonc` の `ratelimits` バインディングも要る。API トークンでの接続は今までどおり動く。
