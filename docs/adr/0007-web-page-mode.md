# ADR 0007: Webページモード（プレゼンのページを縦に並べた公開ページ）

- ステータス: Accepted
- 日付: 2026-10-22
- 対象コード: `app/domain/pageTheme.ts`, `app/application/{slides,pageThemeStyle,webPagePublication}.ts`, `app/components/{PageView,PagePreview,PagePublish,PageThemePanel,SlideShow}.tsx`, `app/components/webpage.css`, `app/lib/{parallaxBackground,safeMarkdown}.ts`, `app/webpage-view.tsx`, `app/webpage-runtime.ts`, `app/server.ts`（`/w/:id`, `/api/notes/:id/webpage`）

## コンテキスト

プレゼンモード（`buildSlides`）は木をそのままスライドの列にできる。これを縦に並べれば、簡単な Web ページになる。既存の公開サイト（`/sites/:pubId`、枝 + JSX テンプレート。のちに廃止: ADR 0003 の追記）とは別の、ノート全体を手軽にページにする機能として作る。

## 決定

1. **ページはプレゼンと同じ規則で作る。** `buildSlides` の結果をそのまま使う（各ルートのタイトルページ、1 枚に収まらない枝は分割。分割の規則は下の「追記: ページ分割の規則」）。ノート全体を 1 サイトにする。
2. **テーマは文書のデータにする。** `MindMapDocument.theme`（`domain/pageTheme.ts`）を content JSON（v2）の任意フィールドとして保存する。そのため同期・Undo・暗号化はそのまま効き、公開ノートならサーバーが読める。同期パッチの `theme` は丸ごと 1 値で扱い、別のセッションが同時に変えると競合になる。無いときは `DEFAULT_PAGE_THEME` を使い、これまでの白いスライドと同じ見た目になる。値はすべて閉じた選択肢か範囲付きの値で、`normalizePageTheme` が唯一の入口になる。
3. **描画は 1 つのマークアップで共有する。** `PageView.tsx` を、スライドショー（variant `slide`）、エディタ右上のプレビューと公開ページ（variant `web`）が共有する。見た目は `webpage.css` の `wp-*` クラスに置き、テーマの値はカスタムプロパティ、閉じた選択肢は `.wp-root` の data 属性（`data-variant` / `data-title` / `data-heading` / `data-effect` / `data-stagger`）で切り替える。
4. **見た目は選ばせ、書かせない。** タイトルページのスタイル（`titleStyle`: 中央 / シンプル（線なし） / 左寄せ / 特大 / 枠 / 塗り、`data-title`）や見出しのスタイル（`headingStyle`: シンプル / 下線 / 縦線 / 帯 / 色、`data-heading`）のような閉じた選択肢をテーマに足していく。既定値（`center` / `simple`）は従来の見た目にする。当初はユーザー CSS（`@scope (.wp-root)` に閉じ込め、at-rule を許可リストで絞る `scopeUserCss`）を持っていたが、廃止した。公開ノートの閲覧者に作者の CSS を見せる以上、閉じ込めの検査を CSS の構文の進化に合わせて保ち続ける必要があり、`wp-*` クラス名も改名できない公開の契約になる。それに見合うほど使われる機能ではなかった。保存済みのテーマに残る `css` は `normalizePageTheme` が捨てる（読み込んで次に保存した時点で消える）。エディタではページを `.wp-frame`（`contain: layout paint`）に入れ、Web 形式の `position: fixed` の背景がアプリを覆わないようにする。
5. **公開ページはサーバーで描く静的 HTML にする。** `/w/:id` は、毎回その時点のノートから `renderToString` で描く（保存＝反映、スナップショットは持たない）。スクリプトは `webpage-runtime.ts`（WebGL 背景とスクロールエフェクト）だけで、無くても全文が読める。CSP は `default-src 'none'` を基本にし、許可するのは自前のスクリプト、Google Fonts、https の画像だけ。Markdown は DOM の無いサーバーでも安全な `renderSafeMarkdown` で描く（生の HTML はテキストにし、URL は http(s) か同一オリジンのパスだけ通す）。
6. **公開の方針はノード公開と同じにする。** 公開ノートだけを、取り消せるランダム ID（`web_pages` 表、ノートに 1 つ）で配信する。`public_epoch` が一致するあいだだけ配信するので、一度非公開やゴミ箱になったノートは、持ち主がもう一度公開するまで止まったままになる。解除すると行を消し、再公開では新しい URL を発行する。
7. **エディタでは「ページモード」1つにまとめる。** スライドと Web ページは同じページ・同じテーマの「1 枚ずつ」か「縦に並べる」かの違いでしかないので、ヘッダーのボタンは「プレゼン」トグル 1 つにする（かつての「プレゼン」「Webページ」の 2 ボタンを統合）。右上のプレビュー（`PagePreview.tsx`）が形式（スライド / Webページ）を切り替えて同じページをその variant で描く。テーマパネルは両形式で共通。形式ごとの操作はプレビューの同じ位置に出し分ける: スライドなら「▶ 開始」（スライドショー）、Webページなら「公開」（`PagePublish.tsx`、`/w/:id`）。公開ページは縦長だけで、スライド形式で公開・Web 形式で全画面再生、はしない。F5 と右クリックメニューからのスライドショー開始はそのまま残す。
8. **背景はプリセットとパラメータで作る。** 1 つのフラグメントシェーダーに 4 種のプリセットを持たせ、色 2 つ・速さ・スクロール追従率（パララックス）を調整できる。任意の GLSL は受け付けない。WebGL が無い・失われたときは、単色の `--wp-bg` になる。`prefers-reduced-motion` ではアニメーションとスクロールエフェクトを止める。

## 影響

- `NodeType` を追加したら、`PageView.tsx` の `NodeContent` にもその描き方を足すこと（足さないとテキストとして描かれる）。
- テーマの項目を足すときは `normalizePageTheme`、`model.arb.ts` の `pageThemeArb`、テーマパネルの 3 か所を更新する。

## 追記: ページ分割の規則（2026-10-23）

当初は「子孫が `SLIDE_MAX_ITEMS`（10）個を超える枝は、セクション（目次）と子ごとのページに分ける」の一択だった。ペルソナを使ったユーザー評価（LT 登壇者・大学講師・企画職）で、3 者ともに次の違和感が出たので、規則を改めた（`application/slides.ts`）。

- 葉だけの長い一覧（課題の洗い出し 15 個、年表など）が、目次 1 枚と、見出しだけのページ 15 枚になる。目次と中身がまったく同じ。
- 判定が項目数だけで、長文 10 行は 1 枚に詰め込まれ、溢れる。
- 目次ページが 2 枚続く・項目 1 つの目次ページが出る。
- 「分けたい」ときに、11 個を超えるまで項目を水増しするか、階層を壊すしかない。

決めたこと（2 回目の評価で出た「s まで縮めて詰め込みすぎ」「項目＋一言メモが 1 行だけのページになる」「深い所の指定が効かない」も反映した）:

1. **収まるかは描いたときの大きさで決める。** `slideFits` が slide 版 `webpage.css` の寸法（cqw）を写した見積もりで、折り返し後の行数・画像・Markdown の高さを足し、見出しとパンくずを除いた余白と比べる。基準は本文サイズ `m`（教室の後ろから読める大きさ）で、`s` は分けようのない 1 項目のための最後の手段。パンくずとページ番号の分はいつも確保するので、同じ枝はどの深さに置いても同じ判定になる。箇条書きの文字サイズ（`Slide.size`）は 4 件以下なら `l`、それ以外は `m`。続きページどうしはそろえる。見積もりが実際の描画と食い違っていないことは `slideFit.browser.test.tsx` が確かめる。
2. **収まらない枝は、子の形で分け方を変え、話す順番はいつも保つ。** 下に 2 項目以上あり、見出しになれる長さ（2 行まで）の子を「トピック」と呼ぶ。
   - 全部がトピック: 子の名前の目次と、トピックごとのページ。
   - 半数以上がトピック（章立てのような語り）: トピックがそれぞれ自分のページを持つ。
   - 半数未満（列挙）や「続けて」の指定: 自分のページを持つのは、「子ごと」を指定した子と、1 枚に収まらないトピックだけ。そういう子がなければ、1 つの箇条書きとして同じ見出しの続きページ（`Slide.part`、「見出し (1/2)」）に、項目をメモ・掘り下げごと切らずに均等な長さで分ける。
   - 自分のページを持つ子があるときは、アウトラインの順に、子の名前の扉（収まらなければ見出しだけ）、その子のページ、間の小さい子を出す。間に挟まる小さい子が一言メモ付きの 1 項目ならその項目名を見出しに、複数なら親の見出しのページにし、扉からの通し番号「(k/n)」を付ける。メモのない葉の並びは扉に全文出ているので省く。「続けて」は扉を、子のページが先頭に来るときだけ出し、小さい子はすべて続きページに残す。
   - 1 枚に収まらない長い段落は見出しに昇格させず、親の見出しの下に単独のページとして置く。文字サイズ `s` はそのページだけに使う。

   評価の途中で試した 2 つの形はどちらも失敗した。全部を語りの順で、トピックごとに切ると、課題の洗い出しが 2 項目ずつに刻まれた（企画職）。「目次に全項目 → 詳細」にすると、章の結論が議論より先に出て、重いトピックの詳細が後回しになった（講師・LT）。いまの形は、細切れを列挙の扱いで、順番の崩れを扉と挟み込みで防ぐ。
3. **無駄な目次を出さない。** 子が 1 つなら目次を出さず、その子を親の位置に並べる。目次の直後が最初の子の目次になるときは、収まる限り親の目次に入れ子で畳む。
4. **パンくずからルートを外す。** タイトルページがすでに何の話かを示している。
5. **ノードごとに分け方を指定できる。** マークアップを持たない方針は保ち、プレビューの「スライドの分け方」（自動 / 子ごと / 続けて、選択中のノード）で `slideSplit` を切り替える。`true`（子ごと）は収まっても子をそれぞれ別のページにし、その祖先も 1 枚には畳まない（深い所で指定しても必ず効く）。`false`（続けて）は子ごとに分けず、続きページの 1 つの箇条書きにする。プレビューには選択中の枝が何ページになるか（`branchSlideCount`）も出す。

しきい値の前後で構成が変わること自体は残る（収まる最後の 1 行を超えると、枝の分け方が変わる）。同じ深さの兄弟の分け方をそろえる案は、ある枝に 1 行足すと無関係な兄弟のページまで変わるので採らなかった。そろえたいときは「子ごと」を使う。
